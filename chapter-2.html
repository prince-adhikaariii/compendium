2.1 The Role of the Operating System Kernel

An Operating System (OS) is foundational system software acting as an intermediary between user applications and hardware components. The core component of the OS is the Kernel, which runs in a privileged hardware state (Kernel Mode).

  • Process Management & Scheduling: The Kernel allocates CPU time slices to multiple active software threads using algorithms like Round Robin or Preemptive Priority Scheduling, giving the illusion of simultaneous execution (Multitasking).
  • Memory Management & Paging: The Kernel manages physical RAM by creating Virtual Memory spaces mapped into fixed-size blocks (Pages). If physical RAM fills up, idle pages are swapped to secondary disk storage (Page File / Swap Partition).
  • Device Drivers & I/O Isolation: Drivers provide a unified API, shielding software developers from raw device-specific hardware instructions.

2.2 File Systems and Path Resolution

File Systems structure binary data blocks on secondary storage into human-readable directories and files. Common file systems include NTFS (Windows), ext4 (Linux), and APFS (macOS).

Data is located using file paths:

  • Absolute Path: The complete reference starting from the root directory (e.g., C:\Users\Student\Documents\notes.txt or /home/student/notes.txt).
  • Relative Path: Path reference specified relative to the current working directory (e.g., ./Documents/notes.txt).

2.3 User Interfaces: GUI vs. CLI

Users interact with the operating system via two primary interfaces:

  • Graphical User Interface (GUI): Uses visual icons, windows, and pointer interactions (e.g., Windows Desktop, macOS Finder). Highly intuitive, but requires higher system resources.
  • Command Line Interface (CLI): Text-based command input (e.g., Bash, PowerShell). Consumes minimal overhead and allows rapid automation via scripting.

2.4 Software Licensing: Open Source vs. Proprietary

Software distribution rights are governed by legal licenses:

  • Proprietary Software: Source code is compiled, closed, and owned exclusively by a commercial entity (e.g., Microsoft Windows, Adobe Photoshop). Users purchase a limited license to execute the software.
  • Open Source Software (FOSS): Source code is publicly available under licenses like GPL or MIT (e.g., Linux Kernel, Python, Apache). Users can inspect, modify, and redistribute the code freely.

2.5 Process Lifecycle: How a Program Runs

When you double-click an app, it becomes a Process — a program in execution. Every process moves through defined states as the OS scheduler manages it:

Diagram 2.2: A process cycles through New → Ready → Running, sometimes pausing to Wait for I/O, before it Exits

  • New: The process is being created and loaded into memory.
  • Ready: The process is loaded and waiting in a queue for its turn on the CPU.
  • Running: The CPU is actively executing the process's instructions.
  • Waiting (Blocked): The process pauses because it's waiting for something slow, like a disk read or user input.
  • Terminated: The process finishes execution and is removed from memory.

Because the CPU switches between many "Ready" processes extremely fast (in milliseconds), it feels like your phone or laptop is running many apps at once — this illusion is called multitasking.

2.6 Virtual Memory & Paging in Detail

Modern computers often need to run more programs than physically fit in RAM. Virtual Memory solves this by giving every process the illusion of having its own huge, private block of memory.

  • Physical RAM and each program's virtual address space are both split into equal fixed-size blocks called pages (commonly 4KB).
  • A Page Table maps each virtual page to a physical page frame in RAM, so the CPU can translate addresses on the fly.
  • When RAM is full and a new page is needed, the OS moves a rarely-used page out to disk (the Swap File / Page File) — this is called paging out. Too much of this causes "thrashing," which makes a computer feel very slow.
